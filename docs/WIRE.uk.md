# Бінарні формати повідомлень

Corundum дає читачеві вказівник на запис прямо в спільній пам'яті. Найшвидше використати його як структуру: без розбору, копіювання та виділення пам'яті. Але це коректно лише тоді, коли письменник і кожен читач (торговий робот, панель телеметрії, рекордер) однаково розуміють розкладку структури до байта. [`corundum/wire.h`](../include/corundum/wire.h) перетворює цю домовленість на перевірки під час компіляції.

[English](WIRE.md)

## Перевірки

```c
#include <corundum/wire.h>

typedef struct md_quote {
    uint64_t ts_ns;      /*  0  час біржі */
    int64_t  bid_px;     /*  8  фіксована кома, 1e-8 */
    int64_t  ask_px;     /* 16 */
    uint32_t bid_qty;    /* 24 */
    uint32_t ask_qty;    /* 28 */
    uint32_t instrument; /* 32 */
    uint32_t seq;        /* 36 */
    uint16_t venue;      /* 40 */
    uint8_t  flags;      /* 42 */
    uint8_t  reserved[5];/* 43  нулі */
} md_quote;

CRD_WIRE_SIZE(md_quote, 48);
CRD_WIRE_PACKED(md_quote, ts_ns, bid_px, ask_px, bid_qty, ask_qty,
                instrument, seq, venue, flags, reserved);
CRD_WIRE_OFFSET(md_quote, seq, 36);
```

| Макрос | Не компілюється, коли |
|---|---|
| `CRD_WIRE_SIZE(T, n)` | `sizeof(T) != n` |
| `CRD_WIRE_OFFSET(T, f, off)` | поле `f` починається не з байта `off` |
| `CRD_WIRE_PACKED(T, f1, ..., fN)` | сума розмірів перелічених полів не дорівнює `sizeof(T)` (дірка вирівнювання, хвостовий паддінг або поле, якого немає у списку); поле не вирівняне природно (можливо лише з атрибутом `packed` чи прагмами); `alignof(T) > 8`; у C++ також коли `T` не trivially copyable і не standard-layout |
| `CRD_MSG_AS(T, &msg)` | (під час виконання) повертає `const T *` у спільну пам'ять, якщо `msg.size == sizeof(T)`, інакше `NULL` |

`CRD_WIRE_PACKED` приймає до 24 полів. Масив рахується одним полем з повним розміром; вкладена структура рахується одним полем і має мати власний `CRD_WIRE_PACKED`.

Заголовок компілюється лише для little-endian цілей (усі підтримувані: x86-64 і arm64 на Linux та Windows), тож дамп байтів запису означає одне й те саме на кожній підтримуваній машині.

Усі перевірки — це `_Static_assert` / `static_assert`: вони не генерують коду. Набір тестів збирає вісім маленьких програм, кожна з яких порушує одне правило, і перевіряє, що сім із них відхилено, а контрольна збирається (`wire_compile_fail_*` у CTest).

## Правила розкладки, якій ніколи не потрібен паддінг

1. **Лише типи фіксованої ширини:** `uint64_t`, `int32_t`, `uint8_t`... Ніколи `int`, `long`, `size_t`, `bool`, enum чи вказівники: їхній розмір або зміст різниться між компіляторами та процесами.
2. **Поля від 8-байтових до 1-байтових.** Тоді кожне поле вирівняне природно і компілятор не вставляє паддінг, без `__attribute__((packed))` (який змушує до повільнішого невирівняного доступу, і `CRD_WIRE_PACKED` відхиляє його, якщо поле лишається невирівняним).
3. **Розмір кратний 8** за рахунок явних `reserved` байтів, які письменник обнуляє. Записи в кільці вирівняні на 8 байтів, тож це нічого не коштує, а резервні байти — місце для майбутніх полів.
4. **Ціни як цілі з фіксованою комою** (наприклад, `int64_t` з масштабом 1e8), а не `double`: точно, порівнюється через `==`, однакові біти на кожній машині.
5. **Вид запису — у 32-бітному `type` кільця**, а не в корисному навантаженні: читач обирає обробник, ще не торкаючись даних.
6. **Ніколи не змінюйте опубліковану розкладку.** Додайте новий тип запису (або використайте резервні байти, де нуль означає «відсутнє») і зберігайте старий, доки всі читачі не оновляться.

## Читання на місці

```c
crd_msg m;
while (crd_read(&r, &m) == CRD_OK) {
    if (m.type == MD_QUOTE) {
        const md_quote *q = CRD_MSG_AS(md_quote, &m);   /* NULL, якщо розмір не той */
        if (q) on_quote(q);                            /* читає прямо зі спільної пам'яті */
    }
}
crd_release(&r);
```

У C++ те саме робить `corundum::Message::as<T>()`, а `Writer::try_emplace<T>(type, args...)` конструює `T` прямо всередині кільця.

Вказівник дійсний до `crd_release`. Корисне навантаження лежить у пам'яті, до якої письменник теж може писати. Якщо письменнику не довіряєте, скопіюйте запис перед перевіркою (див. [SECURITY.md](../SECURITY.md)).

## Приклад

[`examples/market_data.h`](../examples/market_data.h) описує записи котирування, угоди та heartbeat з усіма перевірками. [`examples/wire_demo.c`](../examples/wire_demo.c) пише їх у кільце, читає на місці та друкує байти одного запису так, як вони лежать у спільній пам'яті:

```
first md_quote, 48 bytes straight from shared memory:
00 00 2a 36 fe 9c 97 17 80 e4 88 3a d4 03 00 00
c0 5c 06 3c d4 03 00 00 03 00 00 00 05 00 00 00
07 00 00 00 00 00 00 00 02 00 00 00 00 00 00 00
bid 42100.50000000  ask 42100.75000000  seq 0
read 4 quotes and 4 trades in place: ok
```

`tests/test_wire.c` вручну, незалежно від визначення структури, будує очікувані 48 байтів котирування і порівнює їх з тим, що читач бачить у кільці на кожному зміщенні буфера, зокрема в точці переходу через кінець.
